## 추천하는 화면과 처리 경계

- 기존 자료실에 manifest·앱 이름·설치 안내·오프라인 안내를 추가합니다. 별도 접속 프로그램은 만들지 않습니다.
- 화면 상태는 「확인 중 → 승인 필요/승인 대기 → 서버가 등록 확인 → 기존 자료실」로 구분하는 방향을 추천합니다. 구체적인 상태 이름은 **추천 설계**이며 원문의 고정 API 상태값이 아닙니다.
- 설치 상태와 기기 승인 상태는 따로 표시합니다. 로그인 성공·설치 완료·승인 버튼 클릭만으로 보호 자료를 열지 않습니다.
- 승인 확인 실패·통신 오류·오프라인에는 보호 자료를 표시하지 않고 안내만 보여 주는 방향을 추천합니다. 보호 응답·키·토큰을 localStorage, sessionStorage, IndexedDB, Cache Storage 등에 저장하지 않는 방향입니다. 오프라인 보호 자료 캐시 금지는 **추천 설계**입니다.
- 후속 사용자 지시로 학생 서버에 WebAuthn 승인·요청 검증을 구현했습니다. 기기 개인키는 운영체제 인증기가 관리하고 브라우저 저장소에는 넣지 않습니다. 공개 설정과 aleph.json은 연결 정보만 전달합니다. 상세 기준은 [접속 앱 계약](../docs/ACCESS_APP_CONTRACT.md)입니다. 기존 Claude 검토는 아래에 원문 그대로 보존하며, 이후 결정은 문서 끝에 기록합니다.
- 화면 숨김과 서버의 접근 거부를 각각 확인합니다. 직접 API 요청으로 화면을 우회해도 승인 전 자료가 반환되어서는 안 됩니다.

## 심판 요청 표

## allowedRoutes 후보

11단계 보호 자료 경로는 기존 7개를 유지합니다. 전체 회귀에서 판정기 허용 경로와 설정의 일치를 확인했습니다.

```text
POST /api/notes
GET /api/notes/:id
PUT /api/notes/:id
DELETE /api/notes/:id
GET /api/announcements
GET /api/announcements/:id
POST /api/notes/:id/restore
```

판정기의 `/api` 없는 표기도 같은 의미로 시험합니다. `restoreRoute`는 마지막 항목과 같습니다.
manifest·아이콘·오프라인 안내·공개 연결 선언은 공개 자산입니다. /api/device는 로그인한 사용자의 등록·확인 전용이며 자료를 반환하지 않아 보호 자료 allowedRoutes에 넣지 않습니다.
학생 서버의 기기 등록 경로와 운영 판정 경로를 구분합니다. 심판 연동은 사용자 지시로 미확인 기록만 남기고 진행 조건에서 제외합니다.
