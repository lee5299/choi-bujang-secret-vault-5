# 12단계 요구사항 표

## 통과 후 사용자 변경 요청 (2026-10-15)

관리자 A 화면은 삭제하지 않고 주석 처리해 보존합니다. 자료실·공개 B에서 A 메뉴를 제거하고 A 화면 스크립트는 실행하지 않습니다. 주석 처리한 화면 원본·A 전용 JS는 배포 정적 파일에 포함하지 않습니다. 관리자 API·권한·기기 검사 기능은 유지하고 공개 B에 사용자·기기별 정보를 추가하지 않습니다. 이전의 통과 후 A 반영 계획은 이 요청으로 대체합니다.


## 사용자 순차 재작업: 만들기 2 (2026-10-15)

- 공개 작전실 B에 1~11단계의 정상·금지 요청, 기대 결과, 실제 API 결과, 요청 ID, 확인 시각·출처·커밋·상태를 **하나의 표**로 제공합니다. 기존 T01~T38에 첫 화면 기본 대조 S01을 더한 56행이며 공식 41종의 목록이나 일대일 매핑이 아닙니다.
- 실제 응답이 없는 행은 미실행입니다. 가상·SQL·운영·수동 절차는 HTTP 실측으로 바꾸지 않습니다. 5xx·연결 실패·보호 API의 요청 ID 누락은 확인 미완료입니다. 주소·행·계정 별칭이 다른 결과를 자동으로 합산하지 않습니다.
- 공개 첫 화면 200과 보호 API 정상 사용자 200을 따로 셉니다. 정상 허용과 금지 거부 실측이 모두 있어야 한다는 조건을 표시하고, 보호 API 정상 실측이 없으면 조건 미충족으로 둡니다. 공식 41종은 0/41 미실행을 유지합니다.
- 파일 내보내기·가져오기는 사용자가 요청하지 않은 구현 선택이므로 새 흐름에서 제외했습니다. 선택한 행의 응답 메타데이터는 같은 출처의 새 자료실 창에서 UUID 기반 연결로 전달합니다. 본문·자료 ID·계정 정보·토큰·서명은 전달하지 않습니다.
- 계정·자료 소유권·연속 시험 조건은 사용자 확인 사항입니다. method·경로가 같은 응답을 받았다는 이유로 해당 조건이나 서버 로그 대조를 검증했다고 쓰지 않습니다. 화면 연결 결과는 현재 페이지 메모리에만 남습니다.
- 사용자는 테스트 계정의 로그인·기기 확인을 직접 수행하겠다고 했으며 시험에 따른 자료 변경을 허용했습니다. 실제 로그인이 필요한 시점에 안내합니다. 테스트 계정 허용은 별도의 커밋·push·배포·심판 제출 승인으로 간주하지 않습니다.
- 관리자 작전실 A는 사용자 100점 통과 보고 전까지 변경하지 않습니다.

### 사용자 추가 A4: 자료실과 독립된 작전실 페이지

작전실을 전용 HTML·스크립트·스타일의 별도 문서로 구성합니다. 자료실에는 관리자 전용 이동 링크만 두고, 작전실에는 메모 목록·편집기·공지·자료실 스크립트·메모/공지 API 호출을 포함하지 않습니다. `/operations-room` 주소창 HTML 진입은 전용 로그인 문서로 안내하고, 관리자 로그인·기기 확인·서명된 서버 진입 검사 후 작전실만 표시합니다. 기존 A1~A3의 API 권한 검사는 유지합니다. 토큰은 문서별 메모리에만 두며 문서 간 전달·URL·브라우저 저장소에 넣지 않습니다. 검증: `test/operations-page-stage12.test.mjs`, `test/r12-requirements.test.mjs` 자료실 메뉴 회귀.

## 이번 요청의 범위와 기준

사용자 요청은 요구사항 정리와 선택 사항의 추천안 결정입니다. 원문 안의 이어받기·제작 1~3·저장점 명령은 이후 작업의 요구사항으로 읽었습니다. 이번에는 문서만 작성하며 구현·DB 변경·배포·커밋·제출을 수행하지 않습니다.

기준 커밋은 `7ebbf67`(11단계 100점 통과 기록과 공격 유형별 재시험, 2026-10-14)입니다. 루트 README의 11단계 종료 기록과 일치합니다. `aleph.config.json.step`은 현재 11입니다. 사용자의 11단계 통과 보고와 실제 기기 학생 시험의 미실행 기록은 구분해서 보존합니다.

기존 기능 요약:

1. 로그인 검증과 본인 메모 CRUD, 타인 메모 거부 및 원본 DB 직접 접근 방어.
2. 기기 등록·복합 이상 추가 확인·메모/공지/강사 자료/복구 구역 판정.
3. 사용자별 10분 GET 120건 초과 탐지와 회수 제안의 로컬 연습.
4. 메모 한 건 봉인 사본 복구와 별도 시험 정책 복원·감사 기록 보존.
5. 접속 앱 설치 안내·메모리 세션·승인 기기의 매 요청 WebAuthn 서명 검사.

작업 전 미추적 파일 `XDR-01/xdr-1.txt`, `XDR-01/xdr-2.txt`, `docs/PROJECT_PAGE.md`는 다른 작업으로 보존합니다.

## allowedRoutes 후보

추천 결정: 기존 7개를 유지합니다. 이는 /api 표기로 정규화한 판정기의 전체 허용 경로 집합이며, /api 없는 같은 경로도 판정기 시험에 포함합니다.

```text
POST /api/notes
GET /api/notes/:id
PUT /api/notes/:id
DELETE /api/notes/:id
GET /api/announcements
GET /api/announcements/:id
POST /api/notes/:id/restore
```

작전실 표시 때문에 전체 메모 목록·강사 자료·export·관리 경로를 이 목록에 추가하지 않습니다. 로그인·기기 제어 경로는 기존 접속 앱 계약대로 자료 전달 경로와 구분합니다.

추천 결정: 작전실 요약은 **학생 직접 API** `GET /api/operations-summary`(예정)로 제공하고 로그인·승인 기기·이번 요청 서명·서버 열람 범위를 검사합니다. 엔진 중계 허용 경로에는 넣지 않으며, 엔진 경로로 요청한 결과는 M3d로 대조합니다. 운영 자료를 이 API에 공급하는 공식 연결은 여전히 미확정입니다.

현재 `src/device-proof.mjs`의 서명 확인값 발급은 /api/notes·/api/announcements만 대상으로 합니다. 새 요약 API를 기존 서명 흐름에 명시적으로 추가하고 동작·경로·본문 결합을 시험하는 것이 제작 1 완료 조건입니다. 이름만 정해 놓고 현재 호출할 수 있다고 기록하거나 서명 검사를 생략하지 않습니다.
