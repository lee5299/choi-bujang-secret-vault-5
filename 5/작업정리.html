01 · SCOPE

작업 목표와 실제 수행 범위

4단계 화면은 이미 메모를 /api/notes로 처리했습니다. 그러나 로그인 토큰과 공개 키로 Supabase 원본 자료 API를 직접 호출할 수 있는 권한이 남아 있었습니다. 5단계에서는 이 우회 경로를 닫고 정상적인 본인 메모 처리를 유지했습니다.

실제로 변경한 부분

  • public.library_notes의 PUBLIC·anon·authenticated 테이블·열 권한 회수 SQL을 작성했습니다. 사용자가 학습 DB에서 적용했습니다.
  • 화면의 실제 Supabase 공개 키를 제거하고 기존 Auth SDK의 요청을 신규 /api/auth로 연결했습니다.
  • 단계 설정·배포 식별 JSON·학생 자기 점검·시험 기준표를 갱신했습니다.
  • 심판에서 발견한 배포 JSON의 originalApiUrl 누락을 수정했습니다.

확인하고 유지한 부분

  • 브라우저의 직접 메모 DB 호출: 없음. 메모 CRUD 서버 호출로 새로 전환한 작업은 없습니다.
  • 기존 서버의 로그인 검증·세션 확인·소유자 필터·입력 검사를 유지했습니다.
  • 기존 RLS와 소유자 정책 네 개, 서버 역할의 CRUD 권한을 유지했습니다.
  • vercel.json의 기존 nosniff 헤더와 메모 상세 경로 연결을 확인했습니다.

과제의 기본 조건과 추가 점수

구분요구사항대응

이번 문서 작성에서는 코드·설정·DB를 변경하지 않았습니다. XDR 기능과 후속 Git 이력 정리는 별도 기록으로 연결하며, 5단계의 새 기능으로 합산하지 않습니다.

02 · ARCHITECTURE

전체 서비스 구성

메모와 인증 요청은 Vercel 서버 함수를 거칩니다. 화면 파일과 SDK는 정적 파일로 내려받습니다. “서버 함수만 호출한다”는 조건은 메모 자료 요청에 적용되며, SDK를 받는 CDN 요청까지 없다는 뜻은 아닙니다.

실제 서비스 경로직접 요청 거부 확인구현은 있으나 운영 요청 확인 범위 밖
권한 회수와 RLS는 역할이 다릅니다. RLS가 true이고 소유자 정책이 있어도 authenticated에 테이블 권한이 있으면 본인 자료를 원본 API로 직접 조회할 수 있습니다. 이 단계는 직접 역할의 권한을 회수했습니다. 서버는 권한이 큰 service_role을 사용하므로 기존 서버의 로그인·소유자 검사가 계속 필요합니다.

정적 배포·서버 함수 실행 설정은 vercel.json, 인증 검증은 verify-login.mjs, SQL 적용은 권한 회수 SQL에서 확인할 수 있습니다. 현재 파일에는 후속 작업이 있을 수 있으므로 5단계 상태는 아래 저장점과 함께 읽습니다.

04 · DECISIONS

주요 판단 로직

호출 관계는 앞의 그림으로 설명하고, 조건과 분기는 이 표로 정리했습니다. 상태 숫자는 코드의 동작이며 실제 시험 여부는 검증 표에서 별도로 표시합니다.

판단 위치조건처리와 의미5단계 작업 성격
메모 서버 입구Bearer 형식·로그인 검증 불통과401. 무인증 요청은 DB 전 단계에서 중단합니다.기존 방어 유지
학생 세션 검증서명은 맞지만 Auth 사용자·세션이 유효하지 않음401. Auth 서비스 장애는 503. 심판 토큰은 기존 별도 검증 경로입니다.기존 방어 유지
입력 검사잘못된 UUID·JSON·필드 / 지원하지 않는 방식·형식400 / 405 / 415. 본문에 소유자를 넣어 바꾸려는 시도도 거부합니다.기존 방어 확인

DB 결과 검사반환 행의 소유자·ID·구조가 기대와 다름502·일반 오류. DB 응답을 그대로 믿고 화면에 내리지 않습니다.기존 방어 확인
Auth 서버허용 경로·메서드·Origin·grant·본문 검사token/user/logout만 전달. password/refresh_token만 허용. Origin 헤더가 있을 때 정해진 출처와 대조합니다.신규 Auth 경계 제한
Auth 응답상위 오류 또는 정상 응답의 필요 필드 누락일반 오류와 허용 코드로 제한. 상위 429→429, 5xx→503, 그 외 실패→400. 잘못된 정상 응답→502.신규 오류·응답 최소화
권한 회수 SQL회수 후 테이블·열·상속 권한 남음 / 서버 ACL 변동·CRUD 누락예외로 트랜잭션 중단. 정상 조건에서 COMMIT. 오류 시 ROLLBACK 안내.신규 적용 보호
배포 JSON 생성5단계 이상에서 원본 주소 누락·HTTP·쿼리·인증정보·fragment 포함빌드 오류로 중단. 올바른 HTTPS 경로는 originalApiUrl로 출력합니다.심판 오류 후 누락 수정

originalApiUrl은 심판이 직접 접근 검사를 보낼 주소입니다. 이 필드가 없으면 직접 접근 차단이 되어 있어도 검사 대상이 전달되지 않습니다. 주소를 적는 것 자체가 DB 접근 권한을 부여하거나 회수하지는 않습니다. 실제 값은 설정 파일에서 확인하고, 이 문서에는 키·토큰·계정 ID를 복제하지 않습니다.

npm.cmd run bundle은 커밋·설정·변경 파일명·규칙 이름·설명과 그 실행의 실제 공개 HTTP 자기 점검을 제출 JSON으로 묶습니다. 소스 전체 ZIP이나 DB 백업을 만드는 명령이 아닙니다. 당시 원본 주소 수정 후 묶음은 schema v2·단계 5·변경 파일 5개·규칙 1개·자기 점검 5개로 생성했습니다.

bundle-notes.json과 artifacts/submission.json은 Git 제외 자료입니다. submission.json은 후속 제출로 바뀔 수 있어 고정된 5단계 증거 파일로 취급하지 않습니다. 5개의 자기 점검을 A/B 계정 시험이나 운영 심판 판정으로 해석하지 않습니다.

구현·검증 과정에서 보완한 기술 항목

  • 테이블 GRANT만 보지 않고 PUBLIC·역할 상속·열 ACL까지 확인했습니다.
  • 직접 권한이 남거나 서버 역할 권한이 변하면 SQL 트랜잭션을 중단하도록 했습니다.
  • Auth 전달 경로·메서드·grant 제한, 일반 오류·필요 응답 필드·no-store를 적용했습니다.
  • 기존 SDK를 실제로 사용하면서 가상 응답으로 로그인·갱신·사용자 조회·로그아웃을 검증했습니다.
  • 메모·Auth 서버 함수가 빠져 있던 패키지 기준표와 시험을 실제 API 목록에 맞췄습니다.

자세한 항목 설명은 기존 추가 조치 정리에서 확인할 수 있습니다. 위 항목을 모두 사용자가 개별적으로 지시했다고 단정하지 않고, 구현 과정의 보완으로 기록했습니다.

‘.git 노출’·‘simple.json’·‘x-original-uri’의 작업 귀속

확인된 사실과 미확인 사항을 분리합니다.
후속 기록에는 data.json과 public/data.json의 Git 이력 정리 및 재추적 방지 근거가 있습니다. 이는 별도 Git 기록 정리로 연결합니다. simple.json 노출 차단 또는 x-original-uri 헤더 차단의 구현·시험 근거는 확인하지 못했습니다. 이름이 다른 자료를 같은 조치로 바꾸어 적거나, XDR에서 처리됐다고 완료 표시하지 않습니다.
