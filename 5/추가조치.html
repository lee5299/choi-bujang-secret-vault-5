요구사항과 추가 조치

자료 요청을 서버 한곳으로 모으면서 무엇을 요구받았고, 어떤 보완을 더했는지 구분한 기록입니다. 5단계 작업 기록을 바탕으로 작성한 읽기용 정리본입니다.

기본 요구단계의 필수 방어
추가 점수과제에 명시된 세 조건
추가 조치구현·검증 과정의 보완
오류 수정요구사항 누락 해결
핵심 흐름요구사항추가 조치오류와 수정확인 근거기록 범위

어떤 길을 닫았나

화면의 메모 요청은 이미 서버 함수를 사용했습니다. 이번 단계는 로그인 토큰으로 원본 DB를 직접 호출할 수 있던 권한을 회수하고, 화면에 남은 공개 키도 서버로 옮기는 작업이었습니다.

브라우저메모 읽기·추가·수정·삭제
→
Vercel 서버 함수로그인·소유자 검사
→
Supabase서버용 권한으로 처리
차단한 경로
브라우저 → 공개 키와 로그인 토큰 → 원본 메모 Data API 직접 조회·수정

이 그림은 메모 요청 흐름입니다. Auth도 공개 키 제거를 위해 별도의 서버 함수로 연결했습니다.

과제에 명시된 요구사항

아래 항목은 추가로 만든 기능이 아니라 원래 목표·기본 조건·추가 점수 조건에 해당합니다.

구분요구사항실제 대응
기본 요구메모 요청을 서버 함수로 모으기브라우저의 직접 DB CRUD 호출 제거직접 메모 호출이 없음을 확인했습니다. 기존 /api/notes CRUD와 로그인·소유자 검사를 유지했습니다.
기본 요구원본 메모 테이블의 직접 권한 회수PUBLIC·anon·authenticated 접근 차단학습용 public.library_notes 권한 회수 SQL을 준비했고, 학생이 적용했습니다. 다른 테이블과 메모 행은 수정하지 않았습니다.
기본 검사서버 전용 키·시드 표식 미노출공개 정적 파일·브라우저 묶음 검사공개 화면과 정적 import로 연결된 CDN 파일을 검사했습니다. 키·표식 패턴이 검출되지 않았습니다.
추가 점수허용 경로 등록/aleph.json의 allowedRoutes실제 메모 API 다섯 경로를 대조하고, 배포 JSON에 경로 목록을 포함했습니다.
추가 점수첫 화면 보안 헤더nosniff 또는 CSP기존 vercel.json의 nosniff 설정을 유지했습니다. 실제 배포 응답에서 헤더를 확인했습니다.
추가 점수화면 공개 키 제거키는 서버에서만 사용기존 Auth SDK의 요청을 /api/auth로 연결했습니다. 로그인·갱신·로그아웃 구조를 유지하며 화면의 실제 공개 키를 제거했습니다.
Auth 서버 연결은 공개 키 제거 조건을 만족시키는 구현 방법입니다. 이를 과제 밖의 독립된 보안 목표나 원문에 있던 “제작 3”으로 기록하지 않습니다.

구현 과정에서 더한 조치

요구사항을 안정적으로 적용하고 결과를 확인하기 위해 보완한 부분입니다.

권한 검증 보완

테이블 밖에 남을 수 있는 권한 확인

명시적인 열 단위 권한과 PUBLIC·역할 상속을 포함한 실제 접근 권한을 확인했습니다. 테이블 GRANT 조회 하나만으로 회수 완료를 판단하지 않았습니다.

근거: stage5-library-notes-apply.sql / audit.sql
실패 시 보존

검증 실패 시 SQL 전체 롤백

직접 권한이 남거나 서버용 CRUD 권한이 사라지면 예외를 발생시킵니다. 트랜잭션 단위로 중단해 불완전한 권한 변경을 남기지 않도록 했습니다.

근거: BEGIN · DO 검증 · COMMIT
기존 기능 보호

서버 역할과 정책 유지 확인

서버 역할의 명시적 ACL을 전후 비교하고 SELECT·INSERT·UPDATE·DELETE 권한을 검증했습니다. 기존 소유자 정책 네 개와 RLS도 유지되는지 확인했습니다.

근거: SQL 검증 블록 / 학생 적용 후 조회
Auth 경계 제한

필요한 인증 요청만 허용

Auth 서버 함수는 token·user·logout 경로와 정해진 메서드만 처리합니다. 원본 DB나 임의 URL로 요청을 전달하는 범용 프록시로 만들지 않았습니다.

근거: api/auth.js
응답 최소화

키·사용자 메타데이터 노출 줄이기

오류는 일반 메시지와 허용한 코드로 응답합니다. 인증 응답에 서버 키, 사용자 이메일·메타데이터를 포함하지 않고 no-store를 설정했습니다.

근거: api/auth.js / test/auth.test.mjs
검증 보완

실제 SDK 흐름을 가상 응답으로 시험

로그인·토큰 갱신·사용자 조회·로컬 로그아웃을 실제 SDK로 실행해 서버 연결을 시험했습니다. 가상 시험 통과를 실제 계정·운영 판정으로 표현하지 않았습니다.

근거: test/auth.test.mjs
기준표 정합성

현재 API 목록과 패키지 기준표 맞추기

기존 기준표가 메모·Auth API를 포함하지 않아 시험이 실패했습니다. 실제 API 목록과 기준표를 맞추고 동적 메모 경로도 확인했습니다.

근거: package/baseline-functions.json / 패키지 시험
자료 보관

실행 코드와 단계 기록 분리

중첩 저장소를 루트로 정리하고 단계별 기록을 분리했습니다. SQL은 실행 자료로 연결하고, 캡처·로컬 사본·제출 산출물은 Git에서 제외했습니다.

근거: 5/README.md / .gitignore
요구사항 오류 수정

로컬 설정은 있었지만 배포 JSON에는 없었다

심판 결과 S05_ORIGINAL_URL_MISSING에서 원본 주소 누락이 발견됐습니다. 원본 DB의 접근 권한 문제와 구분해야 하는 설정 전달 오류였습니다.

문제원인수정
배포 /aleph.json에 원본 주소 없음aleph.config.json에는 주소가 있었지만 배포 JSON 생성 코드가 내보내지 않음5단계부터 쿼리 없는 HTTPS 주소를 검증하고 originalApiUrl을 출력. 자기 점검에도 주소 일치 검사 추가

관련 파일: scripts/deployment-identity.mjs · test/r5.test.mjs · src/attack-check.mjs
수정 커밋: 5f247b2 · 당시 실제 배포의 원본 주소 일치를 확인

이 조치는 빠진 요구사항을 바로잡은 수정입니다. 추가 보안 기능으로 집계하지 않습니다.

5단계와 XDR의 기록 경계

XDR 처리 여부 별도 확인 필요
