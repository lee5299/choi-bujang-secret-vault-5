## 검토 순서

1. `AGENTS.md`·`CLAUDE.md`·`docs/workflows/requirements.md`를 읽습니다.
2. `git status --short`·`git log -1`을 확인하고 `9/README.md`의 인수 기준과 대조합니다.
3. 안내 원문 `docs/requests/stage9.txt`와 GPT가 작성한 `9/요구사항.md`를 대조합니다.
4. `docs/DETECT_EVENTS.md`·`scripts/detect-test.mjs`·`src/detect.mjs`를 읽고 판정 계약과의 차이를 확인합니다.
5. 요구사항 파일 끝에 날짜·검토자·행별 지적과 최종 결과를 기록합니다. 코드는 수정하지 않습니다.

특히 확인할 것은 Q1~Q7입니다. 현재 탐지 사건에는 네트워크·기기·판정이 없으며,
사용자별 burst_read 제안은 안내의 복합 조건·기기 한 개 대상과 다릅니다.
현재 판정 응답 다섯 항목이나 decide의 request에 임의 필드를 더해 해결하지 않습니다.
후보 사유·규칙 이름은 검토용이며 실제 RULE_IDS·운영 등록 증거가 아닙니다.

`8/CLAUDE_HANDOFF.md`는 이전 시점 기록입니다. 8단계 현재 상태는 `8/README.md`의 최신 기준과 뒤쪽 보완 기록,
루트 TODO를 따릅니다. 이번 준비에서 배포·DB·심판·제출 JSON을 재검증하지 않았습니다.

## 확인 안내

프로젝트 루트에서 `Invoke-Item '9/CLAUDE_REVIEW.md'`를 실행하거나 파일 목록 **9 → CLAUDE_REVIEW.md**를 누릅니다.
정상 결과는 위 요청 문구가 열리는 것입니다. 검토 뒤에는 **9 → 요구사항.md** 끝에 Claude의 날짜·지적·최종 결과가 있어야 합니다.
기존 서비스의 정상 기준은 본인 메모 CRUD이며 거부 기준은 무로그인 401·타인 메모 404·학생 공지 쓰기 403입니다.
9단계 실제 회수와 재접속 거부는 후속 확인 대상입니다.
