### 제작 2: 사용자별 이동 조회 창

- `findBurstReadSubject(events)`는 안전하게 읽은 GET 사건을 시각순으로 정렬하고 가명 사용자별 이동 10분 창을 계산합니다.
- 어느 창에서든 GET 120건 초과만 다량 조회로 표시합니다. 정확히 120건·정상 30건·다른 사용자 각 100건·10분 밖으로 흩어진 조회는 표시하지 않습니다.
- 정확히 10분 차이는 포함하고 10분보다 오래된 사건은 제외합니다. 순서가 뒤섞였거나 시계의 고정 10분 구간을 가로지르는 사건도 처리합니다.
- GET 아닌 요청·입력의 위조 count·기기·네트워크 추가 필드는 합산·활용하지 않습니다. 입력은 변경하지 않습니다.
- 사건과 집계 상태는 한 호출 안에서만 사용합니다. 이전 호출의 사건이나 회수 상태를 저장하지 않습니다.

제작 2 뒤 `node --test --test-reporter=dot test/*.test.mjs` 전체 218개가 통과했습니다.
이 규칙의 집계 단위는 현재 계약의 사용자입니다. 사용자+기기별 복합 집계는 여전히 공식 계약 필요입니다.

### 제작 3: 별도 회수 제안

`detect(events)`는 조회 창을 최초로 초과한 가명 사용자 한 명에 대해 아래 로컬 계약 응답을 반환합니다.

```js
{ action: 'propose_revocation', reasonCode: 'burst_read', subject: 'learner_fixture' }
```
