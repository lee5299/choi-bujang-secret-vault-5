지금 상황
지금 쓰는 내 자료실을 설치형 웹앱 화면으로 다듬고 기기 승인 흐름을 붙입니다. 따로 설치할 접속 프로그램은 없습니다. 앱을 설치했다는 표시만으로 기기를 믿을 수는 없습니다.


만들 방어 도구
학생은 자기 자료실을 여는 접속 화면(manifest 포함)과 기기 승인 흐름을 만듭니다. 승인 여부는 서버와 판정기가 정하고, 기기 키나 토큰은 브라우저 저장소에 넣지 않습니다.

이번 단계에 들어오는 괴물
설치형 앱 서명 없이 보호 요청
서명 뒤 요청 경로를 변경
서명 뒤 수정 본문을 변경

직접 확인할 것
승인 전에는 자료가 없는가?
승인한 기기에서 기존 화면이 열리는가?
100점 받는 법
기본 조건을 모두 통과하면 70점이고, 아래 항목을 하나 채울 때마다 10점이 더해집니다. 3가지를 모두 채우면 100점입니다. 다시 제출하면 가장 높은 점수가 남습니다.

저장소를 새로 받아 npm install 을 했을 때 오류 없이 끝난다.
src/decider.mjs 가 docs/DECIDER_REQUEST.md 의 요청 이름만 읽고(request.role·identity·device 같은 값은 읽지 않음), 모든 가상 요청에 형식이 맞는 응답을 돌려준다. 응답의 ruleIds 는 모두 RULE_IDS 목록에 있는 이름이어야 한다.
aleph.config.json 의 step 값이 11 이상이다. 단계를 올릴 때 이 숫자도 함께 올린다.

이어받기
이 폴더는 1~10단계까지 만든 같은 자료실이야. 이번에는 11단계 「나만의 접속 앱을 완성합니다」를 할 거야. AGENTS.md와 README.md, 폴더 구조, git 상태, git log -1을 읽고 README의 단계 기록이 마지막 커밋과 맞는지 대조해 줘. 어긋나면 먼저 알려 줘. 현재 기능을 다섯 줄 이내로 요약하고 다른 작업은 보존해. 아직 아무 파일도 고치지 마.


===========================================================================

만들기 1: 제작 1
지금 배포 중인 내 자료실에 설치형 웹앱 설정(manifest)과 기기 승인 상태 표시를 붙여 줘. 앱 이름과 오프라인 안내도 넣되 설치 표시만으로 기기 확인이 끝났다고 쓰지 마. 따로 접속 프로그램을 만들거나 설치하지 마.

확인: 새 화면에서도 기존 보호 요청의 정상·거부 결과가 유지되어야 합니다.

문구 복사
만들기 2: 제작 2
기기 승인을 요청하고 결과를 보여 주는 화면을 붙여 줘. 승인 전에는 보호 자료를 표시하지 말고, 서버가 이 기기를 등록 기기로 확인한 뒤에만 기존 자료실을 열어 줘. 기기 키를 브라우저 저장소에 넣거나 승인 버튼만으로 권한을 준 것으로 처리하지 마.

확인: 승인 전에는 자료가 없고 승인된 기기의 기존 화면은 정상이어야 합니다.

문구 복사
제출 전 확인
이번 변경을 「11단계 저장점」으로 커밋해 줘. 그다음 npm run bundle을 실행해 제출 묶음 JSON과 요약을 보여 줘. 오류가 나면 첫 오류만 고쳐 줘.

참고
공격자는 복호화 키에 접근할 수 있던 엔지니어 4명 가운데 한 명의 집 컴퓨터를 노려, 그 컴퓨터에 깔린 미디어 소프트웨어의 취약점으로 키로거를 심었습니다. 이렇게 얻은 마스터 비밀번호로 회사 금고에 들어가 클라우드 백업 저장소에 접근하는 키를 빼냈습니다. 그 결과 암호화된 고객 금고 백업과 이를 여는 데 필요한 회사 쪽 키가 함께 유출됐고, 라스트패스는 2023년 3월 이를 공개했습니다.

이 단계로 막을 수 있었던 부분
핵심 키와 세션을 관리 대상 업무 기기에만 두고 개인 기기에서는 쓰지 못하게 했다면, 집 컴퓨터 한 대가 뚫려 백업 열쇠까지 넘어가는 일은 막을 수 있었던 부분입니다.
