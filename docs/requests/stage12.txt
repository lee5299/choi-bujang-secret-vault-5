지금 상황
1~11단계를 따로 확인했어도 총공세에서 서로 다른 규칙이 충돌하면 일부 공격이 통과하거나 정상 사용자까지 막힐 수 있습니다.

만들 방어 도구
학생 판정·탐지·회수·복구의 실제 결과를 읽는 탈환 작전실 화면을 만듭니다. 화면의 성공 문구를 통과 근거로 쓰지 않습니다. 마지막 총공세 클리어는 12단계 통과와 41종 공격 방어로 판정하며 차별화는 가산 과제입니다.

이번 단계에 들어오는 괴물

무인증 조회와 타인 메모 조회를 같은 제출본에 연속 전송
미등록 기기 요청 뒤 회수된 신원으로 다시 전송
복구 뒤 서명 없는 변경 요청과 구역 밖 조회를 전송


직접 확인할 것
실제 API 결과와 화면 표시가 일치하는가?
41종 시험의 실행·미실행을 구별했는가?
제공 엔진과 학생 작업의 출처를 밝혔는가?
100점 받는 법
기본 조건을 모두 통과하면 70점이고, 아래 항목을 하나 채울 때마다 10점이 더해집니다. 3가지를 모두 채우면 100점입니다. 다시 제출하면 가장 높은 점수가 남습니다.

저장소를 새로 받아 npm install 을 했을 때 오류 없이 끝난다.
src/decider.mjs 가 docs/DECIDER_REQUEST.md 의 요청 이름만 읽고(request.role·identity·device 같은 값은 읽지 않음), 모든 가상 요청에 형식이 맞는 응답을 돌려준다. 응답의 ruleIds 는 모두 RULE_IDS 목록에 있는 이름이어야 한다.
aleph.config.json 의 step 값이 12 이상이다. 단계를 올릴 때 이 숫자도 함께 올린다.

참고
미국 신용평가사 에퀴팩스는 이미 공개된 아파치 스트럿츠 취약점을 온라인 분쟁 처리 사이트에 패치하지 않았고, 취약점 공개 일주일 뒤 돌린 점검도 이 사이트의 취약점을 찾아내지 못했습니다. 게다가 트래픽 감시 장비의 인증서가 만료돼 있어, 공격자가 서버와 통신하며 자료를 빼내는 동안 이를 잡아내지 못했습니다. 침입은 약 76일 동안 이어졌고, 약 1억 4,550만 명의 개인정보가 유출됐습니다.

이 단계로 막을 수 있었던 부분
점검 결과를 그대로 믿지 않고 실제로 패치가 적용됐는지, 감시 장비가 제대로 돌아가는지를 근거로 확인했다면, 76일 동안 침입을 모르는 일은 줄일 수 있었던 부분입니다.
