지금 상황
도플갱어가 로그인을 흉내 내도 등록되지 않은 기기에서는 자료를 받지 못해야 합니다. 이번 단계에는 따로 설치할 프로그램이 없습니다. 스타터 저장소의 판정기에 기기 등록 규칙 하나를 더하고 npm run decider:test로 확인합니다.

만들 방어 도구
판정 요청 약속(docs/DECIDER_REQUEST.md)에 맞춰 src/decider.mjs에 기기 등록 조건을 넣습니다. 요청에 담긴 로그인·기기 등록 여부·동작·경로만 판단합니다. 기존 자료실 주소와 브라우저 화면은 그대로 둡니다.

직접 확인할 것
등록 기기에서 기존 화면이 열리는가?
판정기에 기기 조건을 넣었는가?
개인키를 공유하지 않았는가?

이어받기
이 폴더는 1~5단계까지 만든 같은 자료실이야. 이번에는 6단계 「등록한 기기만 자료실에 들어옵니다」를 할 거야. AGENTS.md와 README.md, 폴더 구조, git 상태, git log -1을 읽고 README의 단계 기록이 마지막 커밋과 맞는지 대조해 줘. 어긋나면 먼저 알려 줘. 현재 기능을 다섯 줄 이내로 요약하고 다른 작업은 보존해. 아직 아무 파일도 고치지 마.

문구 복사


================================================================
만들기 1: 제작 1
docs/DECIDER_REQUEST.md를 읽고 판정 요청에서 사용자와 기기 등록 여부(deviceRegistered)가 어디에 들어오는지 한 줄씩 설명해 줘. 인증서·CA·서명 키를 새로 만들거나 Git에 넣지 마. 아직 판정기 규칙은 바꾸지 마.

확인: 요청 항목 설명만 나오고 새 키 파일이나 비밀값이 없어야 합니다.

문구 복사
만들기 2: 제작 2
src/decider.mjs에 요청의 기기가 등록 상태(deviceRegistered)일 때만 내 자료실 읽기를 허용하는 규칙 하나를 넣어 줘. 규칙 ID는 device_registered로 RULE_IDS에 추가하고, 미등록이거나 값이 없으면 deny와 이유 코드 device_not_registered로 거부해. 다른 규칙은 건드리지 마.

확인: 등록 기기 요청은 허용, 미등록 기기 요청은 device_not_registered로 거부되어야 합니다.

문구 복사
만들기 3: 제작 3
npm run decider:test를 실행해서 「등록 기기의 정상 요청」은 통과하고 「미등록 기기의 가상 요청」은 deny·device_not_registered로 나오는지 보여 줘. 그 확인 순서를 README에 적어 줘. 이번 과정에는 따로 설치할 접속 프로그램이 없으니 설치 명령을 지어내지 마. 미등록 기기 공격은 심판이 맡아.

확인: 시험 출력에서 등록 기기 통과와 미등록 기기 거부가 모두 보여야 합니다.

문구 복사
제출 전 확인
이번 변경을 「6단계 저장점」으로 커밋해 줘. 그다음 npm run bundle을 실행해 제출 묶음 JSON과 요약을 보여 줘. 오류가 나면 첫 오류만 고쳐 줘.

참고 (실제로 있었던 사고 · 우버 외주 직원 계정이 반복 승인 요청 공격에 뚫린 사고)
2022년 9월 공격자는 악성코드에 감염된 외주 직원 개인 기기에서 흘러나온 것으로 보이는 우버 사내 비밀번호로 로그인을 시도했습니다. 2단계 인증 승인 요청을 여러 차례 보낸 끝에 직원이 한 번 승인하자 계정에 들어갔고, 이후 다른 직원 계정과 슬랙, G-Suite 등으로 권한을 넓혔습니다. 우버는 공격 배후로 랩서스(Lapsus$) 조직을 지목했습니다.

이 단계로 막을 수 있었던 부분
회사에 등록된 기기에서만 로그인을 허용했다면, 비밀번호와 승인 한 번을 얻어 낸 뒤에도 공격자의 기기로 들어오는 일은 줄일 수 있었던 부분입니다.
