# 반복 작업 절차

매 단계 같은 순서로 반복하는 작업의 절차입니다. GPT(`AGENTS.md`)와 Claude(`CLAUDE.md`·`.claude/skills/`)가 **이 문서들을 함께 사용**합니다.
요청을 받으면 해당 절차 문서를 먼저 읽고 그 순서·기록 형식을 그대로 따릅니다. 이전 단계 기록을 다시 조사해 형식을 추측하지 않습니다.

| 상황 | 절차 문서 | Claude 스킬 |
| --- | --- | --- |
| 새 단계 시작: 「폴더 N을 만들어주세요」, 「이어받기」, 안내 원문 전달 | [stage-start.md](stage-start.md) | `/stage-start` |
| 제작 전 요구사항 표 정리·교차 검토 | [requirements.md](requirements.md) | `/requirements` |
| 「제작 k」·「만들기 k」 구현과 기록 | [stage-build.md](stage-build.md) | `/stage-build` |
| 저장점·배포·제출·채점 결과 대응 | [savepoint.md](savepoint.md) | `/savepoint` |
| 보너스 XDR 모듈 제작 1~5 | [xdr-module.md](xdr-module.md) | `/xdr-module` |
| 단계 마감 `N/작업정리.md`·HTML·그림 | [work-summary.md](work-summary.md) | `/work-summary` |

## 공통 원칙

- `AGENTS.md`의 규칙이 이 절차보다 우선합니다. 둘이 다르면 사용자에게 알립니다.
- **최종 총공세는 1~12단계에서 조치한 방어 전체가 한꺼번에 들어옵니다.** 새 단계 작업이 이전 단계 조치를 깨뜨리면 완료가 아닙니다.
  제작·저장점마다 전체 회귀 `node --test test/*.test.mjs`를 실행하고 통과·실패 개수를 기록합니다.
- 실제 실행·가상 시험·미실행을 구분해 기록합니다. 가상 결과를 운영 차단이나 심판 판정으로 쓰지 않습니다.
- 커밋·push·배포·DB SQL 실행·권한 지정·심판 접수는 사용자의 승인 또는 직접 실행으로만 진행합니다.
- 비밀번호·토큰·키·실제 신원·메모 본문은 어떤 기록에도 넣지 않습니다.
- **100점 통과한 단계는 공격 유형과 시험 방법을 [docs/공격유형별-재시험.md](../공격유형별-재시험.md)에 추가합니다** ([savepoint.md](savepoint.md) 7번).
  방어전 개발이 끝나면 이 문서로 1~12단계·XDR 전체를 재시험합니다.

## 8단계에서 얻은 교훈 (모든 단계에 적용)

1. **요구사항 표를 먼저.** 제작 전에 [requirements.md](requirements.md)로 표를 만들고 작성하지 않은 쪽(GPT↔Claude)이 검토합니다.
2. **판정기는 심판 환경에서 동작해야 합니다.** 환경변수·권한표·외부 설정 없이 계약 필드만으로 판단합니다. 설정이 있어야만 허용하는 구조를 만들지 않습니다.
3. **막는 이유를 드러냅니다.** 막는 범주마다 이름 붙은 구역·전용 사유 코드·RULE_IDS 규칙을 둡니다. 「모르는 경로라서 막힘」은 심판이 구역 규칙으로 인정하지 않을 수 있습니다.
4. **신고 경로 = 허용 경로.** `aleph.config.json`의 allowedRoutes는 판정기가 허용하는 경로와 정확히 같아야 합니다.
5. **시험은 심판 조건으로.** 가상 권한표·UUID만 쓰는 시험은 문제를 숨깁니다. 설정 없음·비UUID ID·`/api` 유무를 함께 시험합니다.
6. **결과가 이상하면 로그부터.** Vercel 요청 로그로 심판이 보낸 요청을 확인합니다. 같은 결과가 두 번이면 더 내지 않고 근거와 함께 질문합니다.
- 절차를 바꿔야 하면 사용자에게 먼저 알리고 이 폴더의 문서만 고칩니다. 스킬 파일은 이 문서를 가리키기만 합니다.
