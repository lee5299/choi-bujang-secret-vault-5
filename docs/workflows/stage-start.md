# 단계 시작 (인수·준비)

트리거: 「폴더 N을 만들어주세요」, 「이어받기」, 새 단계 안내 원문 전달.
범위: 코드·설정·DB·배포는 건드리지 않습니다. 안내 원문의 제작·저장점 지시는 후속 작업입니다.

- **「이어받기」만 받았을 때**: 1~3번(읽기·대조·미커밋 구분)과 9번 보고만 합니다. **파일을 만들거나 고치지 않습니다.**
- **「폴더 N을 만들어주세요」 또는 기록 파일 작성 요청**: 1~9번 전체를 하며 **기록 파일만** 만듭니다.

## 순서

1. 읽기: `AGENTS.md`, `README.md`, `TODO.md`, 직전 단계 `N-1/README.md`, 폴더 구조.
   명령: `git status --short`, `git log -1 --format="%H %s"`.
2. 대조: README와 `N-1/README.md`의 마지막 기록 커밋 ↔ `git log -1`, `aleph.config.json`의 `step`, `src/decider.mjs`의 `RULE_IDS`.
   **어긋나면 파일을 만들기 전에 먼저 보고하고 멈춥니다.**
3. 기존 미커밋 작업을 수정 n개·미추적 n개로 세고 「이번 단계 대상 아님」으로 구분합니다. 되돌리거나 함께 커밋하지 않습니다.
4. 안내 원문 저장: `docs/requests/stageN.txt`. 사용자가 준 원문 그대로 저장하고, 비밀값이 섞여 있으면 빼고 알립니다.
5. `N/README.md` 생성 (아래 틀).
6. `TODO.md`에 `## N단계 목표와 미완료 작업` 섹션 추가: 안내 원문 링크, 인수 기준 커밋, 제작 항목 체크박스.
   첫 항목은 `- [ ] 요구사항 표 정리·교차 검토 ([requirements.md](docs/workflows/requirements.md))`입니다.
7. `README.md`의 프로젝트 구조 표에 `N/` 행 추가.
8. `CLAUDE.md`의 「현재 위치」 줄을 갱신합니다.
9. 보고: 대조 결과, 현재 기능 다섯 줄 요약, 만든 기록 파일(이어받기만 했으면 「만든 파일 없음」), 다음 할 일(**요구사항 표 정리 → 교차 검토·반영 → 제작 1**).

## `N/README.md` 틀

```markdown
# N단계: <단계명> — 인수·제작 기록

YYYY-MM-DD, 사용자의 N단계 준비와 `N` 폴더 생성 요청에 따라 인수 상태를 기록했습니다.
안내 원문은 [N단계 요청 자료](../docs/requests/stageN.txt)에 보관했습니다.
첨부 문서의 제작·저장점·bundle 지시는 후속 작업 안내입니다. 이번 준비에서 실행하지 않았습니다.
후속 목표와 미완료 작업은 [루트 TODO](../TODO.md)에서 관리합니다.

## 인수 기준과 대조
- 마지막 커밋: `<짧은 해시>` — `<메시지>`.
- README·직전 단계 기록과 커밋의 일치 여부.
- aleph.config.json step, RULE_IDS. 준비만으로 설정을 바꾸지 않았음.
- 기존 미커밋 작업: 수정 n개·미추적 n개. 이번 준비 대상에서 제외.

## 현재 기능 요약
1. … (다섯 줄 이내)

## N단계 제작 전에 확인한 경계
- 읽은 계약·코드 링크와 확인 결과.
- 현재 계약에 없는 값(임의로 만들지 않을 필드)과 공식 확인이 필요한 항목.
```

## 하지 않는 것

- `N/`에 프로그램 사본 만들기, 학습 DB 자료 복사.
- 단계명·제작 내용 추측. 원문에 없는 항목은 「미전달」로 둡니다.
