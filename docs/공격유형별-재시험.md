# 공격 유형별 재시험 안내 — 1~12단계·XDR-01·02

작성: 2026-10-14 · 10단계 추가: 2026-10-14 (Claude) · 11단계 추가: 2026-10-14 (GPT)
목적: 전체 제작을 마친 뒤 기존 방어가 유지되는지 재시험할 때 사용하는 순서표.
범위: 1~12단계, XDR-01·02, 해당 작업 중 추가 확인한 Git 이력·헤더 우회.
13단계 이후와 다른 XDR 모듈은 아직 포함하지 않습니다.
갱신 규칙: 단계(보너스 XDR 포함)가 100점 통과하면 그 단계의 공격 유형과 실제 시험 방법을 이 문서에 추가합니다
(AGENTS.md, docs/workflows/savepoint.md 7번). 방어전 개발을 마친 뒤 이 문서로 전체를 재시험합니다.
10단계 항목(C8·C9, T23~T30)은 10단계 제작·제출 때 실제로 사용한 시험이며, 사용자 보고로 심판 100점 통과(제출 커밋 dd54ee9).

11단계 항목(C10~C12, T31~T38)은 실제 제작·DB 적용·제출 준비 때 사용한 시험입니다. 2026-10-14 사용자 보고 100점 통과, 직전 제출 준비 기준 커밋 6210ec6(결과 카드 해시는 별도 미제공).

12단계는 2026-10-15 사용자 보고 100점 통과입니다. 직전 확인 배포/main은 9972922이며 결과 카드의 제출 해시는 별도 미제공입니다.

이 문서에서는 상세 구현 대신 ‘무엇을 보내고, 어떤 결과를 확인할지’를 정리합니다.
이번 정리에서는 시험·공격 요청·DB 변경·배포·bundle을 실행하지 않았습니다.
‘기존 확인’은 과거 기록의 요약이며 현재 배포에서 새로 확인한 결과가 아닙니다.

============================================================
먼저 준비할 것
============================================================

1. 시험할 커밋과 배포 /aleph.json의 커밋이 같은지 확인합니다.
2. 자료실의 시험 계정 A·B를 서로 분리한 브라우저 프로필로 로그인합니다.
3. 공지는 강사용 시험 계정 두 개를 사용합니다. 기존 자료 대신 새 가상 시험 자료를 만듭니다.
4. 공격 전후 보존 비교는 비공개로 수행하고 공개 기록에는 동일 여부만 남깁니다.
5. 비밀번호·토큰·키·개인키는 출력·파일 저장·채팅 전달하지 않습니다.
6. 실제 요청은 자신이 관리하는 시험 자료실에서 수행합니다.

시험 결과는 세 가지로 구분합니다.
  [로컬] 가상 요청·가상 DB·가상 경보로 코드의 판단을 확인.
  [자료실] 배포된 API·Auth·학습 DB에 실제 요청을 보내 확인.
  [운영] 공식 엔진의 기기 검증·추가 인증·회수·XDR 연결을 통과하여 확인.

로컬 통과나 자료실의 401을 운영 기기 차단·접속 회수 결과로 바꾸어 기록하지 않습니다.
1단계의 공개 메모는 출발 상태입니다. 최종 재시험에서 다시 공개 상태를 만드는 것은 아닙니다.
3단계 인증은 별도 원문이 없어 4단계 이후 통합 기록과 현재 인증 시험을 기준으로 묶었습니다.

[T01] 로그인 없이 공개 메모 파일 읽기
테스트: 로그아웃한 창에서 배포 /data.json을 직접 요청합니다.
기대: 404, 메모 미반환. 첫 화면 /는 열려도 개인 메모는 나오지 않아야 합니다.
기존 확인: 1단계에서는 공개 상태를 확인했고 이후 공개 파일을 배포에서 제외했습니다.
5단계 이후 실제 HTTP 기록은 /data.json 404입니다.

[T02] HTML·브라우저 파일·설정에서 메모와 키 찾기
테스트: DevTools → Network·Sources에서 첫 HTML과 실제 로드된 JS·설정·응답을 확인합니다.
배포 정적 파일 검사에서 메모 본문·서버 키·시드 표식·Supabase 공개 키의 검출 여부만 기록합니다.
기대: 검사 대상에서 미검출, 첫 화면 Response Headers에 nosniff 유지.
정상 로그인에 필요한 토큰은 비밀값 취급하며, 서버 키가 없어야 한다는 검사와 구분합니다.
기존 확인: 5단계 당시 HTML·정적 import로 연결된 CDN 파일 10개를 실제로 검사했습니다.
모든 동적 로딩 파일이나 옛 배포까지 검사한 결과는 아닙니다.

[T03] 공개 Git의 과거 커밋으로 삭제된 메모 파일 읽기
테스트: 아래 두 읽기 명령을 실행하고 GitHub Code·Commits에서도 해당 경로가 남는지 확인합니다.
  git log --all -- data.json public/data.json
  git ls-files -- data.json public/data.json
기대: 두 명령의 출력 없음. 정리된 공개 이력에 해당 데이터 파일이 없어야 합니다.
기존 확인: XDR-02 시기의 추가 조치로 두 경로의 이력을 제거하고 재추적을 방지했습니다.
옛 URL 캐시·포크·이미 받은 사본이나 /.git 노출까지 해결됐다는 뜻은 아닙니다.

[T04] 무로그인으로 메모·공지 API 직접 호출

기존 확인: 공개 GET 요청의 401은 실제 HTTP로, 모든 동작의 거부는 가상 API로 확인했습니다.

[T05] 서명·만료·발급자·대상·역할을 바꾼 토큰
테스트: C1의 notes 시험이 일회성 가상 키로 잘못된 서명·만료·issuer·audience·role 요청을 보냅니다.
실제 토큰을 편집하거나 새 문서에 붙이지 않습니다.
기대: 401, DB 접근 전 거부. 유효한 정상 토큰의 본인 요청은 성공.
기존 확인: 가상 Auth·JWT 시험. 모든 위조 조합을 실제 배포에 보낸 결과는 아닙니다.

[T06] 로그아웃·세션 종료 뒤 옛 토큰 재사용
테스트: C1에서 서명 만료 전인 옛 토큰을 유지한 채 Auth 세션을 종료하고 모든 CRUD를 재요청합니다.
새 로그인은 허용되고 별도 B 세션은 유지되는지도 함께 확인합니다.
기대: 종료 세션은 401, 새 정상 세션은 허용, 메모 보존.
운영 재시험: 화면의 로그아웃 버튼만 확인하는 것으로 끝내지 말고,
실제 Auth 세션 종료 뒤 옛 토큰 요청과 재로그인을 별도로 확인합니다. 토큰은 메모리에서만 처리합니다.
기존 확인: 가상 세션 재생 시험. 실제 자동 갱신·옛 토큰 재사용 전체는 별도 확인 대상입니다.

============================================================
4단계 — 다른 사람의 메모 읽기·변경·덮어쓰기
============================================================

[T07] 메모 ID만 바꿔 타인 자료 접근
테스트: A가 만든 시험 메모 ID에 B 세션으로 GET·PUT·DELETE를 보내고 A/B를 바꿔 반복합니다.
각 계정의 본인 메모 추가·읽기·수정·삭제를 먼저 확인합니다. 메모 보존도 공격 전후 비교합니다.
기대: 본인 POST 201, GET·PUT·DELETE 200. 타인 GET·PUT·DELETE 404·not_found_or_not_owner.
기존 확인: 실제 A 조회 200·B 조회 404, B 수정·삭제 거부 보고가 있습니다.
반대 방향의 실제 ID 시험과 당시 모든 상태 숫자는 충분히 기록되지 않아 재시험해야 합니다. 로컬 C1은 양방향 검사.

[T08] 본문·쿼리의 소유자·역할·사용자 번호 위조
테스트: C1에서 POST·PUT 본문에 owner_id·role 등 허용하지 않은 항목을 추가합니다.
쿼리의 사용자·소유자 값으로 다른 사람의 목록이나 자료를 선택하는 시도도 비교합니다.
기대: 금지 본문 항목은 400·field_not_allowed. 쿼리는 인증된 소유자 조건을 바꾸지 못함.
기존 확인: 가상 API에서 소유자 고정·목록 필터·허용 필드 제한 확인.

[T09] 타인 메모의 기존 ID로 새 메모 추가
테스트: C1의 중복 ID·상대 ID POST를 실행합니다. 실제 시험은 새 가상 시험 메모만 사용합니다.
기대: 409·id_conflict, 기존 메모·소유자 보존. 사용하지 않은 정상 ID의 추가는 201.
기존 확인: 가상 DB 시험. 실제 배포에서의 덮어쓰기 시도는 별도 확인 대상입니다.

5단계 및 추가 조치 — 서버 우회·원본 DB·URL 헤더
============================================================

[T10] 공개 키 또는 공개 키+로그인 토큰으로 원본 DB 직접 요청
테스트: 메모 요청이 Network에서 /api/notes만 사용하는지 확인합니다.
이후 비공개 시험 도구에서 원본 API의 시험 메모 한 건을 키 단독 GET,
키+시험 세션 GET·PATCH로 요청합니다. PATCH는 현재와 동일한 제목을 사용합니다.
키·토큰은 공식 비밀 입력/기존 세션에서 메모리로만 읽고 공개 기록에는 상태와 보존 여부만 남깁니다.
기대: 직접 조회·수정 거부, 메모 미반환·변경 없음. 서버 API의 본인 CRUD는 정상.
기존 확인: 실제 키 단독 GET 401, 인증 GET·PATCH 403, 서버 API 전후 메모 보존 true.
권한 조회: Supabase SQL Editor → stage5-library-notes-audit.sql의 읽기 조회만 실행합니다.
anon·authenticated 직접 권한 false, 서버용 CRUD true를 확인합니다. 적용 SQL을 다시 실행하는 시험은 아닙니다.

[T11] X-Original-URL·X-Rewrite-URL로 인증 경로 우회
테스트: 무로그인 /에 각 헤더 값을 /api/notes로 넣어 GET합니다.
반대로 /api/notes GET에 각 헤더 값을 /로 넣고, POST+X-Original-URL도 확인합니다.

기대: /는 HTML 200 유지, 보호 API·Auth 사용자 조회는 401. 헤더로 자료 처리나 인증을 선택하지 못함.

테스트: 명령 구분자+명령 결합 신호와 구분 문자 하나만 있는 경보를 비교합니다.
기대: 명확한 반복 명령 삽입 block 후보. 문자열을 실제 시스템 명령으로 실행하지 않음.

공통 경계: 같은 주소·패턴의 3분 안 7/8건, 수준 9/10, 서로 다른 주소, 시간 창 밖,
중복 경보, 한 번/두 번 인코딩된 요청 인자를 C6에서 비교합니다.
기존 확인: 오프라인 모듈과 가상 접속 재생.
확인 위치: xdr → web-injection → result.json의 counts, check.json의 fixtureReplay.
기본 fixture 기대: block 8·alert 9·record 9, 공격 거부 8/8, 정상·애매한 통과 각각 9/9.

[X07 / 두 모듈 공통] 차단 결과 위조·정상 공유 주소 오차단·만료 규칙 재사용
테스트: C6에서 정상 경보에 위조 block 결과를 붙이고, 공격과 정상이 주소를 공유하는 경우를 재생합니다.
경보 기준 15분 만료 전후와 중복 실행, 기본 live 모드의 fixture 규칙 제외도 확인합니다.
기대: 근거 없는 규칙 생성 없음, 정상 오차단 0건, 만료 뒤 통과, 기존 판정 응답 보존.
check.json의 normalBlocked·normalAddressBlocked는 0, baseResponsesPreserved는 true여야 합니다.
기본 fixture의 expiredRulesPassed 기대는 XDR-01 9개·XDR-02 7개입니다.
운영 연결: 실제 Wazuh 경보 수신·검증된 출발 주소·엔진 추가 검사·차단 적용을 별도로 실측해야 합니다.
현재 가상 block과 fixtureReplay의 deny를 실제 자료실 접속 차단 완료로 기록하지 않습니다.
이전 Jev 웹 준비와 별도 미커밋 작업은 최종 오프라인 XDR-01·02 방어 시험 범위와 구분합니다.

============================================================
전체 재시험 순서와 기록 방식
============================================================

1. 배포 커밋 대조, 새 시험 계정 자료와 비공개 전후 비교 준비.
2. C0로 전체 로컬 회귀.
3. A/B 본인 정상 CRUD → T01~T11 실제 자료실 점검.
4. C2~C4 → 공지 정상 읽기·강사 직접 API → T12~T20.
5. C5 → T21. 운영 회수 연결이 있으면 T22, 없으면 미확인 기록.
6. C8 → C9 → T23~T29 복구 시험, 바로 이어서 T30(1~9단계 대표 공격 재전송).
   복구 시험은 새 가상 시험 메모만 사용하고, 정책 복원은 시험 정책 저장소에만 적용합니다.
7. C10 → C11 → C12 → T31~T38. 실제 승인 기기의 기존 정상 요청과 경로 재작성도 별도 확인.
8. C13 → T39~T41. A의 관리자 제한과 B의 요청별 증거·미실행 분리를 확인.
8a. C6 → C7 → X01~X07 결과 파일과 오차단·만료 확인.
9. 운영 기기·재확인·회수·XDR 연결 항목은 실제 연결 환경에서 별도 시험.
10. 대상 외 자료 보존 비교, 정상 요청 재확인, C0 최종 회귀.

매 항목에 남길 것:
  시험 ID / 대상 커밋 / 환경(로컬·자료실·운영) / 방법 / 기대 / 실제 / 보존 여부 / 결과 출처.
  실행하지 않은 항목은 ‘미실행’, 연결이 없으면 ‘운영 연결 미확인’으로 적습니다.
  HTTP 5xx·네트워크 실패는 공격 거부 성공으로 처리하지 않습니다.
  상태 코드·고정 사유·동일 여부만 공개 기록에 남기고 메모 본문·토큰·키는 제외합니다.
