# 판단 용어와 해석 기준

작성: 2026-10-16. 목적은 GPT·Claude가 같은 표현과 변수에 같은 뜻을 적용하도록 근거와 적용 범위를 함께 보관하는 것입니다.
이번 작성은 문서 정리이며 변수 이름·판단 코드·시험 기대값을 변경하지 않았습니다.

## 사용하는 순서와 기록의 지위

1. 이번 사용자 요청과 AGENTS.md를 먼저 확인하고 해당 절차·요청 계약을 읽습니다.
2. 이 문서에서 용어·해석 ID를 찾고 **적용 모듈·상태·근거**가 이번 작업에도 맞는지 확인합니다.
3. 기존 해석이 맞으면 요구사항·구현 기록에 해석 ID를 연결합니다. 다른 상황이면 차이를 적고 새 결정을 남깁니다.
4. 코드와 문서가 다르면 문서만 믿고 완료로 보고하지 않습니다. 실제 구현과 시험을 대조하고 차이를 작업 기록에 남깁니다.

이 문서는 공식 계약을 확장하거나 새 요청을 만드는 명세가 아닙니다. 상태는 다음과 같이 구분합니다.

| 상태 | 뜻 |
| --- | --- |
| 계약 | 연결된 요청·응답 계약에 있는 정의. 임의 필드 추가 불가 |
| 프로젝트 정책 | 사용자의 요청·검토 반영으로 채택한 판단 기준. 적용 범위 안에서 사용 |
| 현재 구현 | 코드가 실제로 검사하는 조건. 이름만으로 더 강한 의미를 부여하지 않음 |
| 미확정 | 근거·운영 계약·검증이 부족함. 가정으로 채우지 않고 TODO에 연결 |

과거 단계의 완료 기록과 임시 지시는 현재 정책의 대체물이 아닙니다. 공식 자료는 기술 정의의 근거이고, 프로젝트가 정한 수치·확인 정책은 별도로 표시합니다.

## 적용 순서·미확정 경계

- privilege의 확신도 경계는 0.85 이상 block, 0.5 이상 alert, 그 아래 record입니다. 기존 판단이 record 후보일 때 수준 5~8의 관련 관찰 확인 정책을 더합니다. 최소 alert는 판단의 하한이며 모든 수준 5~8을 같은 결과로 강제하는 뜻이 아닙니다.
- 수준 0~4·9·10~16, 무효 수준 및 설명 부족은 “5~8 확인 정책”만으로 결론을 내리지 않습니다. 나머지 패턴 조건과 입력 처리 기준을 따릅니다. 무효 수준이라는 이유만으로 명확한 다른 근거까지 사라진다고 가정하지 않습니다.
- 일반화한 문장이 모든 한글·영문 변형을 처리한다고 단정하지 않습니다. 지원하지 않는 새 표현은 해석 결정과 긍정·부정·실패 반례를 함께 추가합니다.
- 실제 평소 목록·업무 일정·계정 연결·세션 회수 계약은 이 표로 확정하지 않습니다. 미확정 작업은 [TODO](../TODO.md)에 두고 공식 계약 확보 후 해당 행의 상태를 갱신합니다.
- persistence(XDR-04)의 낮은 관련성 변경도 alert로 남긴다는 비교 결과는 기록되어 있지만, 이 문서 작성으로 다른 모듈의 코드를 일괄 통일하지는 않았습니다. 같은 용어라도 범위가 다르면 차이를 기록합니다.
