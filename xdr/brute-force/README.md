## 현재 제작 상태

2026-10-08 다시 전달받은 만들기 1~5가 현재 기준입니다. 이전 Jev 요청·시험 기록은 아래에 당시 상태로 보존합니다.

| 만들기 | 구현·확인 | 범위 |
| --- | --- | --- |
| 1 · 경보 읽기 | `read-alerts.mjs`의 다섯 항목·민감값 제외, 경보 28건·출력 28줄 확인 | 확인용이며 판단 파일에서 호출하지 않음 |
| 2 · 패턴 목록 | `patterns.json`의 password_guessing·password_spraying, MITRE 근거 한 줄씩 확인 | 근거 없는 패턴 추가 없음 |
| 3 · 판단 모듈 | `decide.mjs` 맨 위 패턴 상수, 동기 `decide(alert)` 하나, import·외부 호출·파일 입출력 없음 | 단일 파일 격리 시험 통과, API 키 불필요 |
| 4 · 알림·차단 | 새 `respond.mjs`에서 알림 누적·별도 거부 규칙·15분 만료·경보 번호·정상 주소 제외 | 시험 재생 완료, 실제 운영 연결 미확인 |
| 5 · 시험 경보 | 실행 후 result.json counts: block 10·alert 9·record 9, 정상 오차단 0 | 로컬 가상 시험 결과 |

`decide.mjs`는 입력 경보와 내장 패턴만 사용하고 판단 결과만 반환합니다.
원본 Wazuh 경보 또는 확인용 다섯 항목을 받을 수 있으나, 확인용 출력에서 제외된 추가 집계 정보는 복원하지 않습니다.
명확한 필수 조건은 0.95, 정상은 0.1입니다. 필수 조건이 부족한 로그인 실패는 0.5에 수준·건수·짧은 시간·반복·T1110 신호를 더하되 0.85 미만입니다.
단일 경보 집계는 같은 모듈 인스턴스의 메모리만 사용합니다. 파일을 다시 불러오면 집계도 초기화됩니다.
개별 요약 경보의 판단은 그 경보에 담긴 건수·시간·다계정 신호를 사용합니다. reason에는 패턴 이름 또는 '패턴 없음'만 반환합니다.

`respond.mjs`의 추가 검사는 기존 ZTNA 응답을 보존합니다. 시험용 가상 규칙을 운영 기본 모드에 적용하지 않습니다.
실제 연결에는 공식 검증 주소·규칙 조회·허용된 거부 응답 콜백이 필요하며, 현재 요청 계약에는 IP가 없습니다.
기존 `src/decider.mjs`의 starter.deny는 유지합니다. 운영 엔진 소스코드를 학생에게 요구하지 않습니다.
기존 `connect.mjs` 호출은 `respond.mjs`로 재내보내어 호환성을 유지합니다.

이전 Jev 웹 시험 준비 코드와 화면은 로컬의 미커밋 작업으로 보존하며 이번 제출에서 제외합니다.
이전 `scripts/xdr-local.ps1` 숨김 키 입력 도구는 현재 오프라인 CLI에서 사용할 필요가 없습니다.
실제 Wazuh 사건 수신·운영 ZTNA 접속·심판 판정·새 배포 확인은 수행하지 않았습니다.

## XDR-01 준비: 작업 기록 (2026-10-07)

목표: 같은 주소·같은 계정의 반복 로그인 실패를 모아 명확한 공격만 차단 후보로 만들고,
애매한 시도는 알림, 정상 이벤트는 기록으로 남기는 보너스 방어 도구를 준비합니다.
ZTNA의 기존 판정 규칙에 확인 단계를 추가하는 부품이며, 기존 규칙은 보존합니다.

### 완료한 인수 확인

- `AGENTS.md`, 루트 `README.md`, `5/README.md`, XDR 안내·가상 경보·실행기와 Git 상태를 읽었습니다.
- 판정 규칙은 `src/decider.mjs`에 직접 정의되어 있습니다. 현재 `RULE_IDS`는 `starter.deny`이며,
  `decide(request)`는 모든 요청을 거부하는 시작 틀입니다. 외부 규칙 파일을 읽는 연결은 없습니다.
- `docs/DECIDER_REQUEST.md`의 요청·응답 계약을 확인했습니다. 현재 요청에는 출발 IP가 없으므로,
  주소 차단을 실제 판정기에 연결하려면 운영 엔진이 확인한 주소를 제공하는 계약이 필요합니다.
  임의 요청 필드를 만들어 연결하거나 정상 요청 통과를 확인했다고 기록하지 않습니다.
- `xdr/fixtures/brute-force.json`에는 가상 경보 28건이 있습니다. 원본은 수정하지 않았습니다.
- `scripts/xdr-run.mjs`는 `xdr/brute-force/decide.mjs`의 `decide(alert)`를 호출하고,
  `xdr/brute-force/result.json`에 경보별 판단과 `block`·`alert`·`record` 건수를 씁니다.
- 프로젝트에 `XDR-01/` 작업용 폴더를 만들었습니다. 인수 확인 당시 Git 미추적 항목은
  `XDR-01/`뿐이었으며, 그 안의 기존 요청 파일은 보존합니다.

## XDR-01 제작과 가상 시험 (2026-10-07)

위 준비 기록은 제작 전 상태입니다. 이후 구현과 현재 확인 결과를 아래에 기록합니다.

### 제작 파일과 이유

- `xdr/brute-force/read-alerts.mjs`: 원본을 수정하지 않고 시각·주소·가상 계정·수준·설명 다섯 항목만 추출합니다.
  문서용 주소·가상 계정만 반환하고, 민감한 값처럼 보이는 설명과 추가 원문 필드는 제외합니다.
- `xdr/brute-force/patterns.json`: 공식 MITRE ATT&CK [T1110.001](https://attack.mitre.org/techniques/T1110/001/)과
  [T1110.003](https://attack.mitre.org/techniques/T1110/003/)에서 확인한 비밀번호 추측·스프레이 패턴을 등록했습니다.
  패턴마다 이름·조건·근거 한 줄·출처를 적었습니다. 숫자 기준은 MITRE 지정값이 아니라 이번 연습의 기준입니다.
- `xdr/brute-force/evidence.mjs`: 안전하게 뽑은 설명과 검증한 건수로 근거를 구성합니다.
  비밀번호 값은 사용하지 않습니다. 같은 비밀번호를 시도했다는 요약 신호만 사용합니다.
- `xdr/brute-force/decide.mjs`: 0.85 이상 block·0.5 이상 alert·그 아래 record를 반환합니다.
  명확한 근거는 0.95, 정상 이벤트는 0.1을 사용하며 이 숫자는 확률로 보정된 모델 평가값이 아닙니다.
  단일 로그인 실패는 같은 주소·계정별 3분 창으로 합산하고 경보 ID 중복과 이미 합산된 경보는 다시 더하지 않습니다.
  애매한 경우만 주입된 Jev 함수에 패턴과 수치·불리언 신호를 전달합니다.
  미연결·잘못된 응답·예외·시간 초과는 원문 오류를 출력하지 않고 alert·0.5로 처리합니다.
- `xdr/brute-force/connect.mjs`: 확신도와 명확한 근거를 함께 확인한 후보만 별도 거부 규칙으로 기록합니다.
  Jev 점수만으로 주소 전체 차단 규칙을 만들지 않습니다. 차단 유효 기간 중 정상 이벤트를 공유하는 주소도 제외합니다.
  근거 경보 번호와 경보 시간 기준 15분 만료를 붙이고 동일 주소의 겹치는 차단 후보는 합칩니다.
  `withXdrCheck`는 기존 판정 함수·운영 주소 확인·규칙 조회·거부 응답 콜백을 받는 추가 검사 부품입니다.
  `decide(request)`의 요청 필드와 응답 다섯 항목을 바꾸지 않으며 가상 규칙은 기본 운영 모드에서 적용하지 않습니다.
- `scripts/xdr-run.mjs`: 기존 결과 형식을 유지하면서 이 모듈의 실행 후 알림·가상 규칙·확인 결과를 기록합니다.
  다른 XDR 모듈과 기존 판정 규칙은 보존합니다.
- `test/xdr-brute-force.test.mjs`: 정상 오차단·민감 설명 제외·시간 창·중복·Jev 실패·만료·추가 검사 부품을 가상 시험합니다.
- 루트 `README.md`·`TODO.md`: 현재 실행 방법과 운영 연결의 미완료 사항을 갱신했습니다.

### 실행과 확인 결과

- `node --test test/xdr-brute-force.test.mjs test/xdr-run.test.mjs`: 가상 시험 12개 통과.
  첫 시험 오류는 민감한 설명 제외 후 정상 이벤트로 분류된 경우였습니다.
  `decide.mjs`의 입력 유효성 확인을 먼저 하도록 한 곳을 수정하고 재실행했습니다.
- 경보 읽기: 원본 28건과 추출 28줄, 각 줄의 필드 다섯 개 일치를 확인했습니다.
- `npm.cmd run xdr:run -- brute-force`: 실제 로컬 실행 후 `xdr/brute-force/result.json`을 생성했습니다.
  같은 명령을 다시 실행하여 결과를 갱신했습니다. 두 실행 모두 block 10·alert 9·record 9입니다.
- `node --test test/*.test.mjs`: 기존 기능을 포함한 가상 시험 44개 통과.
- `xdr/brute-force/check.json`: 정상 이벤트 9건, 정상 이벤트 block 0건, 정상 주소 차단 0건.
- `xdr/brute-force/deny-rules.json`: 차단 후보 10건의 주소 규칙 9개. 같은 주소의 두 경보를 한 규칙에 묶었습니다.
- 가상 추가 검사 부품 시험에서 공격 주소는 거부, 정상 주소는 기존 판정 함수로 넘어갔습니다.
  허용하는 가상 기본 함수를 썼을 때 정상 요청 통과를 확인했고, 현재 starter.deny의 거부도 그대로 보존됨을 확인했습니다.
- `src/decider.mjs`·`aleph.config.json`·원본 경보는 수정하지 않았습니다.
  단계 5·배포 주소·발급자·허용 경로·원본 API 주소는 기존 구현과 로컬 대조했고 judgeIssuer를 유지했습니다.
  배포 주소의 현재 동작을 이번 작업에서 새로 확인하거나 배포하지는 않았습니다.

### 다시 실행하고 결과 보기

```powershell
npm.cmd run xdr:run -- brute-force
```

편집기에서 `xdr` → `brute-force` → `result.json`의 `counts`와 `check.json`을 누릅니다.
정상 예상: 정상 이벤트는 record, 애매한 시도는 alert, 정상 오차단 0건.
거부 예상: 명확한 공격은 block 후보로 기록되고, 가상 모드의 유효한 주소 규칙과 일치하면 추가 검사에서 deny.
`alerts.log`는 매 실행마다 누적되며 원문 경보·계정·비밀번호·토큰은 쓰지 않습니다.

### 저장점과 실제 연결 범위

저장점 이름: `보너스 xdr-01 저장점`. 제작 저장점 커밋은 `869daa4`입니다.
가상 결과·가상 규칙·민감값 없는 알림과 이번 구현·시험·문서를 저장점에 포함합니다.
