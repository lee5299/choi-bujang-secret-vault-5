실행: `node xdr/known-cve/read-alerts.mjs`.

정상 결과는 JSON 24줄입니다. 비밀값·요청 원문은 출력되지 않아야 하고 잘못된 묶음은 읽기 오류로 거부되어야 합니다.

제작 2에서는 머리글 JNDI 조회·인자 JNDI 조회·취약점 점검 도구 흔적 세 패턴에 이름·조건·한 줄 근거·공식 출처를 적었습니다. 도구 흔적은 보조 신호이며 이름·단어만으로 악용을 확정하지 않습니다. 최신 로컬 시험은 해당 모듈 7개·XDR 32개·전체 회귀 328개 통과입니다.

패턴 확인: **xdr → known-cve → patterns.json**. 재확인 명령: `node --test test/xdr-known-cve.test.mjs`.
정상은 패턴마다 한 줄 근거가 있는 상태이며 근거 누락·개행·잘못된 출처는 시험에서 거부되어야 합니다.

제작 3은 패턴 세 개를 내장한 동기 `decide(alert)`만 내보냅니다. 외부 의존·파일 입출력·네트워크 없이 세 항목을 반환하며 확신도 0.85 이상 block, 0.5 이상 alert, 미만 record입니다. 이유는 패턴 이름이며 근거가 없으면 `no_matching_pattern` 상태를 반환합니다.

최신 로컬 검증은 해당 모듈 11개·XDR 36개·전체 회귀 332개 통과입니다. 원본 24건의 가상 판단은 **block 8·alert 4·record 12**이며 공식 정답·실제 차단 결과가 아닙니다. 임의 단어·높은 수준·반복 횟수만으로 차단하지 않습니다. 상세 점수·출력·검증 한계는 [제작 기록](../xdr/known-cve/README.md)에 있습니다.

재확인: `node --test test/xdr-known-cve.test.mjs`. 파일 목록의 **xdr → known-cve → decide.mjs**에서 내장 상수·판단 코드를 확인합니다. 정상은 시험 11개 통과이며 명확한 조회는 block, 애매한 후보는 alert, 일반 정상 이벤트는 record여야 합니다.

## 제작 4 결과

`respond.mjs`가 원본 경보와 판단을 다시 대조한 뒤 차단 후보 8건만 규칙에 넣습니다. 각 규칙은 경보 시각부터 15분 뒤 끝나며 근거 경보 번호를 담습니다. 알림 대상 4건과 차단 후보 8건은 `xdr/alerts.log` 끝에 한 줄씩 추가했습니다. 이전 알림은 그대로 보존했습니다.

가상 요청을 다시 흘린 결과: 공격 **8건 거부**, 알림 대상 **4건 통과**, 기록 대상 **12건 통과**, 각 규칙이 만료된 뒤 **8건 통과**입니다. 관찰한 정상·애매한 요청이 같은 시간대에 같은 주소를 쓰면 그 주소의 차단 규칙을 만들지 않는 시험도 통과했습니다.

기존 ZTNA의 거부·추가 인증 요구는 먼저 처리하고 그대로 유지합니다. ZTNA가 판정기에 보내는 정보에는 출발 IP가 없어 실제 운영 접속과 연결하지 않았습니다. 시험용 규칙은 기본 운영 모드에서는 읽거나 적용하지 않습니다. 관찰하지 못한 미래의 정상 사용자까지 IP만으로 구별할 수 있다고 주장하지 않습니다.

실제 실행한 명령: `npm.cmd run xdr:run -- known-cve`.
파일 목록에서 **xdr → known-cve → check.json → fixtureReplay**를 누릅니다. 정상은 공격 8건만 거부되고 나머지 16건은 통과한 결과입니다. 같은 명령을 다시 실행하면 알림은 추가로 쌓이지만 규칙의 만료 시각은 바뀌지 않습니다.

관련 시험 19개·XDR 시험 44개·전체 시험 340개가 통과했습니다. 별도 에이전트의 보안 코드 검토에서 수정이 필요한 문제는 발견되지 않았습니다. 검토는 코드 읽기로 수행했으며 실제 운영 접속 시험이 아닙니다.

## 제작 5 결과 (2026-10-15)

`npm.cmd run xdr:run -- known-cve`를 이번 요청에서 새로 실행했습니다. [result.json](../xdr/known-cve/result.json)의 `counts`는 **block 8·alert 4·record 12**, 합계 24건입니다.

정상 이벤트 차단은 **0건**입니다. 공개 화면·상태 확인·로그인 성공·정적 파일·본인 메모·세션 유지·공지 조회·로그아웃인 원본 경보 `kc-17`~`kc-24` 여덟 건을 따로 대조했고 모두 record였습니다. 명확한 공격이 아닌 `kc-09`~`kc-24` 전체 16건에도 block은 없습니다.

[check.json](../xdr/known-cve/check.json)의 `normalBlocked`·`normalAddressBlocked`는 모두 0입니다. 이 파일의 정상 건수 12는 판단 코드가 record로 분류한 수치이며, 별도로 확인한 정상 사례 여덟 건과 구분합니다. 요청을 다시 흘린 결과도 공격 8건 거부·알림 대상 4건 통과·기록 대상 12건 통과·규칙별 만료 후 8건 통과입니다.

XDR 관련 시험 44개와 전체 시험 340개가 통과했습니다. 오차단이 없어 판단 코드를 수정하지 않았습니다. 기존 코드·원본 경보·다른 모듈 결과 14개 파일과 이전 알림 전체를 보존했고, 이번 알림 12줄만 파일 끝에 추가했습니다.

다시 실행할 명령: `npm.cmd run xdr:run -- known-cve`.
파일 목록에서 **xdr → known-cve → result.json → counts**, 이어 **check.json → normalBlocked / normalAddressBlocked**를 누릅니다. 정상 예상은 8·4·12와 오차단 0건이며 정상 사례가 block이면 원인을 확인해야 합니다.

위 결과는 시험용 경보와 가상 요청을 사용한 확인입니다. 실제 운영 연결·배포·GitHub 업로드·심판 제출은 이번에 수행하지 않았습니다.

## 제출 준비 (2026-10-15)

판단 파일만 새 임시 폴더에 복사해 독립 실행을 확인했습니다. block 8·alert 4·record 12와 정상 차단 0건이며 XDR 시험 44개·전체 시험 340개·로컬 빌드가 통과했습니다. 저장할 파일 26개와 비밀값 검사 결과는 [제출 전 확인](제출전확인.md)에 정리했습니다. 실제 비밀값은 없었고 제외 기능 시험에 넣은 가짜 주소 한 곳은 실제 개인정보와 구분했습니다.

설정은 일반 단계 12와 기존 판정 규칙을 유지합니다. 제출 준비 당시에는 커밋·GitHub 업로드·배포·심판 접수 전이었으며, 이후 사용자가 승인한 범위의 실행 결과를 아래에 기록합니다.

## 심판 분류 오류 보완 (2026-10-15)

사용자가 `X03_AMBIGUOUS_NOT_ALERT`와 정상 이벤트의 기록 건수 불일치를 보고했습니다. 점수와 정상 기록 오류의 코드는 제공되지 않았습니다. 이전 코드가 취약점 목록 조회·머리글의 중괄호 흔적·점검 도구와 비슷한 이름·라이브러리 이름 네 건을 record로 낮춘 것이 원인이었습니다.

실행 코드 변경은 `decide.mjs`의 확신도 분기 네 줄에 한정했습니다. 이 네 종류의 약한 흔적은 확신도 0.5의 alert로 반환하며, 명확한 조회 구문의 block 분기와 일반 정상 이벤트의 record 분기는 유지했습니다. 경보 번호나 배열 순서를 판단 조건으로 쓰지 않습니다. 패턴 상수·문자열 해석·respond.mjs·기존 ZTNA 판정 규칙·원본 경보는 변경하지 않았습니다.

관련 시험에서 먼저 오류를 재현한 뒤 수정했습니다. 기존 시험은 애매한 경보가 block이 아닌지만 확인했는데, 이를 alert로 정확히 확인하도록 고쳤습니다. XDR3 관련 시험 20개·전체 XDR 시험 45개·전체 시험 341개가 통과했습니다. 다른 1~12단계 시험 기대값은 변경하지 않았습니다.

`npm.cmd run xdr:run -- known-cve`를 실제 실행해 result.json과 check.json을 갱신했습니다. 결과는 **block 8·alert 8·record 8**, 정상 이벤트·정상 주소 차단은 각각 **0건**입니다. 가상 요청은 공격 8건 거부·애매한 8건 통과·정상 8건 통과·규칙별 만료 후 8건 통과입니다. 기존 알림을 지우지 않고 이번 실행의 알림·차단 후보 16줄을 추가했습니다.

로컬 보완을 확인한 당시에는 새 커밋·GitHub 업로드 전이었으며 이후 실행 결과를 아래에 따로 기록합니다. 이 결과를 심판 재통과로 보고하지 않습니다. 사용자가 최종 제출 버튼을 직접 누르는 지시는 유지합니다. 다시 실행할 명령은 `npm.cmd run xdr:run -- known-cve`, 화면에서 확인할 곳은 **xdr → known-cve → result.json → counts**와 **check.json → normalBlocked / normalAddressBlocked**입니다.
